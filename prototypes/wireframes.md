# FitMeal 原型线框与交互标注

> 版本：v0.1
> 对应实现：`web/`、`server/app.py`
> 运行入口：`http://127.0.0.1:8765/app/`
> 截图目录：`web/screenshots/`

## 1. 原型目标

这一版原型用于验证一件事：用户输入少量条件后，能不能拿到一张可以直接执行的结果卡片。原型不追求完整产品体验，也不包含登录、支付、历史记录和用户反馈。

输入区固定保留四类必须条件：场景、目标、时间、现有食材。过敏和地域作为可选条件。替换和营养查询会额外显示原食材、查询食材和重量。

## 2. 首页线框

```text
┌─────────────────────────────────────────────────────────────────────┐
│ FitMeal 轻食令                        服务正常 · 食谱 208 条          │
├───────────────────────────────┬─────────────────────────────────────┤
│ 先试一个例子                   │ 结果区                              │
│ [自烹饪] [外食] [替换] [安全]  │                                     │
│                               │  还没有结果。                      │
│ 一句话描述 [________________]  │  先设置条件，再生成这一餐。        │
│ 场景        [自动判断 v]       │                                     │
│ 目标        [减脂 v]           │                                     │
│ 时间上限    [20] 分钟          │                                     │
│ 地域偏好    [不限 v]           │                                     │
│ 现有食材    [鸡胸肉, 西兰花]   │                                     │
│ 过敏 / 忌口 [______________]   │                                     │
│ 附加字段：替换 / 营养查询时显示│                                     │
│              [生成这一餐]      │                                     │
└───────────────────────────────┴─────────────────────────────────────┘
```

设计判断：

1. 输入和结果放在同一屏，用户不用来回翻页确认条件。
2. 示例入口只回填输入，不直接提交，避免用户还没看清条件就得到结果。
3. 结果区先显示条件摘要，再显示推荐内容，方便用户确认系统实际收到了什么。
4. 任何时间都可以修改输入，不锁字段。

## 3. 自烹饪推荐线框

```text
┌───────────────────────────────────────────────┐
│ 推荐 3 道 · 已按食材匹配和营养目标排序         │
│ 条件：减脂 / 20 分钟 / 川渝 / 鸡胸肉、西兰花   │
├───────────────────────────────────────────────┤
│ 香煎鸡胸配西兰花                  匹配度 86    │
│ 25 分钟 · 1 份 · 每份 320g                     │
│ 热量 412 kcal · 蛋白质 46g · 脂肪 12g · 碳水 18g│
│ 食材：鸡胸肉 已有；西兰花 已有；蒜 需补充      │
│ 做法：1. ... 2. ... 3. ...                    │
│ 热量来源：鸡胸肉 58% / 西兰花 21% / 油 16%     │
│ 注意：如果对花生过敏，酱汁需要替换。            │
├───────────────────────────────────────────────┤
│ 第二张卡片                                     │
└───────────────────────────────────────────────┘
```

设计判断：

1. 菜名之后立刻给时间和营养，不把结论埋在长文里。
2. 每张卡片都写明已有食材和缺少食材，用户可以判断这一餐是否真的能做。
3. 热量来源按食材拆开，避免只给一个无法核对的数字。
4. 过敏原不会被普通推荐覆盖；出现风险提示时，提示词与候选结果分开显示。

真实截图：`web/screenshots/01-cook.png`。

```text
┌───────────────────────────────────────────────┐
│ 今晚吃川菜 · 减脂                            │
│ 条件：川渝 / 减脂 / 没有填写过敏项            │
├───────────────────────────────────────────────┤
│ 优先选择                                       │
│ · 清蒸、白灼、凉拌类，先点一份蔬菜             │
│ · 主菜选鸡、鱼、虾，酱汁分开放                 │
│ 控制分量                                       │
│ · 米饭先盛半碗，根据饱腹感决定是否加           │
│ 高风险项                                       │
│ · 水煮类、干锅类、勾芡和油碟容易增加脂肪       │
│ 参考热量区间                                   │
│ · 这一餐预计 520-760 kcal，具体取决于油和主食  │
└───────────────────────────────────────────────┘
```

外食分支不输出品牌级精确营养值。原因是没有可靠的品牌配方和份量数据，直接给一个精确数字会让用户误以为可以追溯。

## 5. 食材替换线框

```text
┌───────────────────────────────────────────────┐
│ 没有米饭，想换一个适合减脂的主食              │
├───────────────────────────────────────────────┤
│ 糙米                                           │
│ 适用：减脂 / 维持；需要提前浸泡和延长烹饪时间   │
│ 营养变化：同等熟重下，膳食纤维更高             │
│ 使用条件：如果时间不足，可以先用即食糙米        │
├───────────────────────────────────────────────┤
│ 红薯                                           │
│ 适用：减脂；蒸或烤，不额外加糖                  │
│ 营养变化：同等重量下热量接近，饱腹感更好        │
└───────────────────────────────────────────────┘
```

替换结果必须带适用条件和营养变化，不能只给一个同义词。没有规则时显示数据缺口。

## 7. 安全拦截线框

```text
┌───────────────────────────────────────────────┐
│ 这个请求不能直接给执行方案                     │
├───────────────────────────────────────────────┤
│ 风险类型：extreme_low_calorie                  │
│ 原因：一天只摄入 500 大卡低于基础代谢需要       │
│ 建议：先咨询医生或注册营养师                   │
│ 如果出现严重或持续症状，请及时就医              │
└───────────────────────────────────────────────┘
```

安全分支不会继续展示食谱、替换或营养数值。过敏请求和极端饮食请求分开处理：过敏应该先过滤候选，只有过滤后没有安全结果时才进入无匹配。

真实截图：`web/screenshots/05-safety.png`。

## 8. 异常与空状态

| 状态 | 页面表现 | 触发条件 |
| --- | --- | --- |
| 空状态 | 提示先设置条件 | 页面刚打开，还没有提交请求 |
| 加载状态 | 显示正在筛选候选和核算营养 | 请求已经发出，结果还没有返回 |
| 服务错误 | 提示无法连接推荐接口，并给出启动命令 | FastAPI 没有启动 |
| 无匹配 | 说明当前数据没有候选，列出可以放宽的条件 | 筛选后候选为空 |
| 信息不足 | 追问缺少的食材、目标或时间 | 推荐前发现必填条件缺失 |
| 安全拦截 | 显示风险类型和处理建议，停止推荐 | 命中安全规则 |

信息不足、无匹配和安全拦截是三种不同状态，不能共用一个通用失败提示。
