# FitMeal 原型线框与交互标注

> 版本：v0.5
> 更新时间：2026-10-10
> 对应实现：`web/`、`server/app.py`
> 运行入口：`http://127.0.0.1:8765/app/`

## 1. 原型目标

当前原型验证的是一条完整的 Dify 链路：用户只输入一句自然语言，浏览器通过本地服务端代理请求 Dify Chatflow，右侧展示 Dify 的最终回答、真实链路信息和端到端耗时。

浏览器不负责判断意图、拆解食材或拼装推荐参数，Dify 不可用时也不会退回本地规则。需要查询菜谱、营养或替换数据时，由 Dify 工作流内部调用 `POST /recommend`。

## 2. 首页线框

```text
┌─────────────────────────────────────────────────────────────────────┐
│ FitMeal 轻食令                    Dify 链路已配置 · 208 道食谱       │
├───────────────────────────────┬─────────────────────────────────────┤
│ 今天这一餐                     │ 推荐结果                            │
│ 直接说出需求，Dify 来完成判断   │ 等待输入                            │
│                               │                                     │
│ [自烹饪] [外食] [替换]         │  先告诉 Dify 这顿饭的边界            │
│ [营养] [安全拦截]              │  可以直接输入，也可以点上方示例。    │
│                               │                                     │
│ 一句话描述                     │                                     │
│ ┌───────────────────────────┐ │                                     │
│ │ 例：我有鸡胸肉、西兰花... │ │                                     │
│ └───────────────────────────┘ │                                     │
│                               │                                     │
│ [ 生成 Dify 建议  -> ]         │                                     │
│ API Key 不会进入前端           │                                     │
└───────────────────────────────┴─────────────────────────────────────┘
```

设计判断：

1. 页面只保留一个自然语言输入框，避免表单字段与 Dify 参数抽取重复维护。
2. 示例按钮只负责填入问题并提交，不在浏览器内运行本地推荐逻辑。
3. 页面直接写明“通过服务端代理请求 Dify”，用户能够识别真实链路。
4. 输入和结果保持在同一屏，提交后不需要跳转页面。

## 3. Dify 成功回答

```text
┌───────────────────────────────────────────────┐
│ 推荐结果                     Dify Chatflow · 21.6 秒 │
├───────────────────────────────────────────────┤
│ ● Dify Chatflow · 真实 API    1,842 tokens     │
│                                               │
│ 这三道菜都能在 20 分钟内完成。                 │
│                                               │
│ 1. 黑椒鸡胸炒西兰花                           │
│    - 鸡胸肉 150g                              │
│    - 西兰花 200g                              │
│    - 约 15 分钟                               │
│                                               │
│ 2. 番茄鸡蛋 ...                               │
│                                               │
│ 这个回答有帮助吗？ [有帮助] [没帮助]           │
└───────────────────────────────────────────────┘
```

展示规则：

1. 标题由前端固定为“Dify 建议已生成”，回答正文只来自 Dify。
2. 链路标签显示 `Dify Chatflow · 真实 API`，耗时使用 `/chat` 的端到端时间。
3. 回答支持基础换行、标题、列表、加粗和行内代码的安全渲染。
4. 前端不再依据本地 `answer_type` 切换食谱、外食、营养或安全卡片。
5. 营养数字、候选筛选和风险规则仍由 Dify 内部数据节点负责，模型只解释和表达。

## 4. 加载状态

```text
┌───────────────────────────────────────────────┐
│ Dify 正在生成      真实链路通常需要 20 至 40 秒 │
├───────────────────────────────────────────────┤
│                 ● ● ●                         │
│    Dify 正在理解需求、读取数据并生成建议...     │
│              完整链路通常需要 20 至 40 秒       │
└───────────────────────────────────────────────┘
```

加载期间提交按钮禁用，结果区标记为忙碌状态，避免重复提交。等待时间较长时明确说明 Dify 正在执行完整链路，不用本地方案制造“秒回”。

## 5. Dify 不可用

```text
┌───────────────────────────────────────────────┐
│ Dify 请求没有完成                 未使用本地规则降级 │
├───────────────────────────────────────────────┤
│ 这次没有拿到 Dify 回答。                       │
│ 请确认 Dify、8765 数据服务和 8766 向量服务都在运行。│
│ 具体错误：Dify 返回异常 / 连接失败 / 请求超时       │
└───────────────────────────────────────────────┘
```

异常状态遵循以下边界：

1. `/chat` 失败后不调用 `/recommend` 生成替代回答。
2. 页面不把本地规则结果包装成 Dify 结果。
3. 错误信息不展示 `DIFY_API_KEY`、完整上游响应或内部配置。
4. 超过等待上限时提示检查 Dify 和两个本地服务。

## 6. 回答级反馈

```text
┌───────────────────────────────────────────────┐
│ 这个回答有帮助吗？ [有帮助] [没帮助]           │
│ 已记录，感谢反馈                               │
└───────────────────────────────────────────────┘
```

反馈事件写入 `POST /feedback`，当前用于验证事件采集和演示复盘：

1. 点击后两个按钮同时禁用，显示提交结果。
2. 请求携带 `/chat` 返回的 `request_id` 和 Dify `message_id`。
3. 当前只记录回答级偏好，不改变本次或下一次推荐排序。
4. 反馈文件属于本地运行产物，不进入公开仓库。

## 7. 独立营养计算页线框

入口：`http://127.0.0.1:8765/app/nutrition.html`。这条链路不经过 Dify，也不调用大模型，用于已知食材和克重时的确定性计算。

```text
┌─────────────────────────────────────────────────────────────────────┐
│ FitMeal 轻食令      推荐首页 | 营养计算 | 数据录入 | 数据总览        │
├───────────────────────────────────┬─────────────────────────────────┤
│ 把食材和克重算清楚                │ 计算结果                        │
│                                   │                                 │
│ 食材                 重量（克）    │ [热量] [蛋白质] [脂肪]          │
│ [鸡胸肉            ] [150      ]  │ [碳水] [膳食纤维]               │
│ [西兰花            ] [200      ]  │                                 │
│ [+ 添加食材]                       │ 分成 2 份后的每份结果            │
│                                   │                                 │
│ 这份食材分成几份 [2]               │ 食材明细 | 重量 | 热量 | 营养来源 │
│ [计算营养]                         │ 鸡胸肉   | 150g | ...  | ...     │
│                                   │ 西兰花   | 200g | ...  | ...     │
│ 营养值来自 nutrition.csv           │                                 │
│ 当前只接收克重                     │ 未识别食材会单独列出并使结果不完整 │
└───────────────────────────────────┴─────────────────────────────────┘
```

交互规则：

1. 食材行可以增加和删除，至少保留一行；支持营养库标准名和已登记别名。
2. 重量输入固定为克，不接受“个 / 瓣 / 碗”等非重量单位。
3. 份数只影响每份结果和每份重量，不改变输入的食材总重。
4. 点击“计算营养”后调用 `POST /nutrition/calculate`，返回整份和每份两个口径。
5. 结果区展示热量、蛋白质、脂肪、碳水和膳食纤维，并给出食材级拆解、热量占比和数据来源。
6. 未识别食材使用 `unresolved` 单独提示，不计入合计；全部未识别时显示补数据提示，不伪造估算值。
7. 空输入、克重不大于 0、份数不在 1 至 100 范围内时，在页面内定位到具体行或字段。
