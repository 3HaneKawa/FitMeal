# FitMeal 轻食令 PRD

> 状态：粗略版  
> 版本：v0.1  
> 更新时间：2026-10-03

## 1. 需求背景

健身人群在饮食决策上存在四个核心摩擦：

1. 知道要吃对，但不知道今晚吃什么。
2. 食谱平台内容丰富，但与健身目标脱节。
3. 健康记录工具偏事后记录，缺少事前决策支持。
4. 外食场景缺少适合健身目标的点餐策略。

### 1.1 竞品情况

| 竞品类型 | 代表产品 | 优势 | 不足 |
| --- | --- | --- | --- |
| 综合食谱平台 | 下厨房、豆果美食 | 食谱丰富、步骤详细 | 营养数据不稳定，缺少健身目标过滤 |
| 健康记录工具 | 薄荷健康、MyFitnessPal | 记录能力强 | 不解决吃什么的问题 |
| 通用 AI 助手 | ChatGPT、豆包、Kimi | 理解和生成能力强 | 营养数据容易编造 |
| 外卖平台 | 美团、饿了么 | 可直接购买 | 推荐目标偏交易和口味 |
| 健身内容社区 | Keep、小红书 | 场景认知强 | 推荐分散，难个性化执行 |

### 1.2 机会点

FitMeal 的机会不是生成更多食谱，而是同时满足五个约束：

1. 健身目标
2. 现有食材
3. 时间限制
4. 口味和地域偏好
5. 自烹饪或外食场景

## 2. 需求概述

FitMeal 轻食令是一个面向健身人群的“今晚吃什么”助手，根据用户的现有食材、健身目标、时间限制、口味偏好和用餐场景，输出可执行的自烹饪食谱或外食选择建议。

### 2.1 产品目标

用户目标：

1. 在 3 次推荐内决定这一餐吃什么。
2. 获得可信的营养估算。
3. 知道外食时如何选择。
4. 尽量使用已有食材。
5. 避免忌口、过敏和极端饮食风险。

业务目标：

1. 验证健身人群对健身餐推荐的真实需求。
2. 建立可评测的 AI 推荐链路。
3. 形成 Prompt、知识库、规则计算和外食建议的产品化原型。

### 2.2 非目标

第一版不做：

1. 账号体系和社交
2. 支付
3. 外卖下单
4. 医疗级营养建议
5. 长期饮食习惯建模
6. 疾病、孕期、未成年人等特殊人群饮食方案

## 4. 需求详情

### 4.1 核心流程

```text
用户输入
  ↓
参数抽取
  ├─ ingredients
  ├─ goal
  ├─ meal_type
  ├─ time_limit
  ├─ flavor_preference
  ├─ region
  └─ allergies
  ↓
意图分类
  ├─ cook 自烹饪推荐
  ├─ eat_out 外食推荐
  ├─ substitute 食材替换
  ├─ nutrition_analysis 营养分析
  └─ unsafe 不安全请求
  ↓
分支处理
  ↓
结构化输出
```

### 4.2 自烹饪推荐评分

| 维度 | 权重 |
| --- | ---: |
| 食材匹配率 | 40% |
| 营养目标匹配 | 30% |
| 时间匹配 | 10% |
| 口味和地域匹配 | 15% |
| 多样性 | 5% |

### 4.3 安全规则

以下情况必须拦截：

1. 用户声明过敏，输出包含过敏原。
2. 极端低热量请求。
3. 连续多天单一饮食请求。
4. 疾病、孕期、未成年人等特殊人群请求。
5. 明显不安全的饮食建议。

## 5. 数据埋点

### 5.1 核心指标

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 首次推荐采纳率 | 用户在首次结果中采纳任一推荐 | ≥40% |
| 三次推荐内决策率 | 换一批不超过 3 次并采纳 | ≥70% |
| 换一批率 | 点击换一批的请求占比 | ≤50% |
| 自烹饪完成率 | 用户反馈已按食谱完成 | ≥30% |
| 外食建议采纳率 | 用户按建议选择外食类型 | ≥40% |
| 安全拦截成功率 | 高风险样例全部拦截 | 100% |
| P95 响应时间 | 从提交到结果返回 | ≤8 秒 |
| 每次成功推荐成本 | 成本 / 成功任务数 | ≤0.1 元 |

### 5.2 埋点事件

| 事件 | 触发时机 |
| --- | --- |
| page_view | 进入首页 |
| input_submitted | 提交输入 |
| intent_result | 意图识别完成 |
| parameter_missing | 参数缺失 |
| recipe_result_shown | 食谱推荐展示 |
| recipe_selected | 用户采纳食谱 |
| recipe_rejected | 用户拒绝食谱 |
| regenerate_clicked | 点击换一批 |
| eat_out_result_shown | 外食建议展示 |
| feedback_submitted | 提交反馈 |
| safety_blocked | 安全拦截 |
| latency_measured | 请求完成 |

## 6. 数据集要求

1. 食谱库：MVP 目标 100 条，当前数据 100 条。
2. 食材营养库：MVP 目标 100 条，当前数据 100 条。
3. 地域外食库：MVP 目标 50 条，当前种子数据 10 条。
4. 目标规则库：MVP 目标 10 条，当前种子数据 4 条。
5. 替换规则库：MVP 目标 30 条，当前种子数据 10 条。
6. 评测集：MVP 至少 20 条。

## 7. 验收标准

### 7.1 质量验收

| 指标 | 标准 |
| --- | --- |
| 意图识别准确率 | ≥95% |
| 参数抽取准确率 | ≥90% |
| 食材匹配率 | ≥80% |
| 营养达标率 | ≥85% |
| 营养数值一致率 | 100% |
| 食谱可执行率 | ≥90% |
| 外食建议合理率 | ≥80% |
| 过敏拦截率 | 100% |
| 极端请求拦截率 | 100% |
| JSON 格式通过率 | 100% |

### 7.2 回滚条件

1. 营养数值严重错误。
2. 过敏原未拦截。
3. 极端饮食建议未拦截。
4. JSON 解析失败率超过 5%。
5. P95 延迟持续超过 15 秒。
6. 单次推荐成本超过预算 3 倍。
