## 1. E1 目标与结论

E1 只解决一件事：**先把 v1 需要验证的能力范围冻结下来**。能力清单必须从 PRD 反推，不能从当前代码或现有零散用例反推，否则评测会变成用测试迁就实现。

本阶段完成：

1. 对 PRD 的 F1–F15 逐项标注 v1 范围。
2. 冻结四个用户意图：`cook / eat_out / substitute / nutrition_analysis`。
3. 冻结五类风险：S1–S5；其中 S1 是候选过滤，S2–S5 是安全拦截。
4. 冻结五类边界：信息缺失 / 目标冲突 / 食材无匹配 / 超量 / 多目标。
5. 冻结四类语言变体：口语 / 方言词 / 中英混 / 长文本。
6. 明确 F10 仍为 `v1_promised_not_ready`：最小反馈事件记录已实现，但对话反馈理解、偏好持久化和排序闭环未完成，12 条正式反馈用例不能从范围中删除或算作通过。
7. 明确知识库后置检索不进入 v1 决策链路评测，只作为未来补充能力。

## 2. 范围分类

| 范围 | 含义 | 处理方式 |
| --- | --- | --- |
| `v1_required` | v1 必须交付并可验证 | 必须有正向、反向和边界用例；M3 门前必须达标 |
| `v1_promised_not_ready` | PRD 已承诺、当前尚未完整实现 | 保留评测位置；允许部分链路先落地，但未完成的对话与偏好闭环不能算通过 |
| `v1_out_of_scope` | PRD 明确不属于 v1 | 不进入主评测集；如果产品文案或接口宣称支持，则视为回归缺陷 |
| `future_post_v1` | 后置能力，当前不参与决策 | 接入后新增独立评测块，不得替代事实来源 |

## 5. 用例口径

E1 同时冻结用例原则，E2 起按此写具体用例：

- 不把“必须返回某个食谱 ID”作为唯一通过条件。
- 使用可机检的语义约束，例如“至少一道使用米饭或虾仁”“所有推荐不得含花生”“至少一道满足减脂区间”。
- 每条用例必须能定位失败阶段：意图、参数、安全、Python、解释、输出格式。
- 每条用例必须标记 `capability_id`、`prd_ref`、`split` 和 `severity`。
- 过敏场景 S1 的正常行为是过滤后继续推荐；只有在风险类型属于 S2–S5 时才拦请求。
- 12 条对话式 F10 用例保持 `not_ready`；最小反馈事件记录只能证明字段和接口可用，不能替代对话理解、偏好持久化和排序闭环。
- 知识库检索不参与事实校验；营养事实永远以 Python 和数据表为准。

## 6. PRD 反哺规则

1. 失败先归因：实现没做到，还是 PRD 没定义清楚。
2. 实现问题：修实现，保留用例。
3. PRD 问题：先更新 PRD，再更新评测集。
4. 行为变化：旧用例转为回归用例，不直接删除。
5. 只读验收集只用于验收，不用于调参。
6. 不能用放宽规则、修改期望值或删除用例来制造通过。

## 8. 营养计算器的确定性测试

独立营养计算器归入 F4 和 F12，不新增能力编号。它不调用 LLM，也不经过 Dify，因此更适合用固定输入验证数值和边界。

必须覆盖：

| 场景 | 输入 | 期望 |
| --- | --- | --- |
| 正常计算 | 鸡胸肉 150g、西兰花 200g，1 份 | 返回总热量、蛋白质、脂肪、碳水、膳食纤维和食材级拆解 |
| 份数换算 | 同一组食材，2 份 | 总营养不变；每份营养和每份重量按 2 等分，验证不重复四舍五入 |
| 别名归一 | 西红柿 100g | 先归一为番茄，再按番茄营养表计算，来源字段保留 |
| 部分未识别 | 鸡胸肉 50g、火星蔬菜 100g | 鸡胸肉仍计算；火星蔬菜进入 `unresolved`，不计入合计 |
| 全部未识别 | 火星蔬菜 100g | 合计为 0，`complete=false`，页面提示补营养或别名数据 |
| 非法输入 | 空列表、缺食材名、克重为 0 / 负数、份数为 0 / 1.5 / 101 | 返回 HTTP 400，错误信息定位到具体字段 |
| 来源可追溯 | 任一已识别食材 | 返回 `source`、`source_ref`、`source_name` 等已有字段，缺失时明确保留空值 |
| 依赖隔离 | 停止 Dify 和向量服务，仅保留 FastAPI | 计算接口仍能完成，证明该路径不依赖 Dify |

通过条件：

1. 所有已识别食材的数值可由 `data/nutrition.csv` 每 100 克数据复算，小数处理规则一致。
2. 未识别食材不能静默按 0 计入合计，也不能用相近食材、模型估算或默认值顶替。
3. 份数只改变每份结果，不改变输入总重量和整份合计。
4. 接口只接收克重；如果后续增加“个 / 瓣 / 碗”等输入，必须同时增加单位换算和对应回归用例，不能只在页面上放开输入。

当前状态：以上场景已经沉淀到 `scripts/check_nutrition_calculator.py`，并在本轮离线回归中复跑通过。该结论只证明确定性计算和输入边界可用，不代表真实用户验证或成品认可度。
