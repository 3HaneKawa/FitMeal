# 墨刀 AI 低保真原型提示词

> 配套文档：`docs/PRD.md` 第 10 节「低保真原型生成规格」
> 用途：生成 FitMeal 轻食令 Web 端低保真交互原型，不用于高保真视觉稿或上线验收
> 使用方式：墨刀新建 Web / 桌面端项目，画板设为 1440 × 1024，然后复制下方主提示词

## 1. 使用顺序

1. 在墨刀中创建 Web 端项目，画板使用 1440 × 1024。
2. 把「主提示词」完整粘贴到墨刀 AI。
3. 如果一次生成数量有限，先用主提示词生成 P01 至 P07。
4. 主流程生成后，再粘贴「补全提示词」生成 P08 至 P11。
5. 最后按「生成后检查」逐项核对，不要直接把第一版 AI 结果当作最终原型。

## 2. 主提示词（直接复制）

```text
你是一名资深产品设计师。请基于我上传的《FitMeal 轻食令 PRD》生成一套 Web 端低保真交互原型，优先读取 PRD 第 10 节。不要生成高保真视觉稿，不要使用真实照片、复杂插画、渐变、玻璃拟态或重度阴影。目标是让人快速看懂“用户说一句话，系统给出安全、可追溯、可执行的饮食建议”这一产品闭环。

【产品背景】
FitMeal 面向有明确健身目标、但没有稳定饮食计划的人，主要服务减脂、增肌、维持期和外食频率高的用户。用户可以输入现有食材、目标、时间、地域和忌口，系统输出自烹饪建议、外食建议、食材替换、营养说明或安全提醒。用户已知食材和克重时，还可以进入独立营养计算器，得到整份与每份营养结果。

【原型范围】
只画 Web / 桌面端，画板 1440×1024。使用顶部导航 + 两栏布局：首页左侧为需求输入，右侧为建议结果；营养计算页左侧为食材录入，右侧为计算结果。导航包含 FitMeal 轻食令、推荐首页、营养计算、数据工具。采用低保真灰阶线框，只保留一个绿色主色和一个橙色警示色。

【必须生成的页面】
请按顺序生成 P01 至 P07，每个页面只表达一个主要状态，并给画板使用清楚的名称。

P01 首页-空状态：
顶部显示 FitMeal 品牌、推荐首页、营养计算、数据工具和“服务已连接”状态。左侧标题为“把这一餐说清楚”，说明“用一句话说明现有食材、目标、时间和忌口”。下方有五个示例入口：自烹饪、外食、替换、营养、安全拦截。再放多行输入框，占位文案为“例：我有鸡胸肉、西兰花和鸡蛋，减脂，想 20 分钟内做完”，主按钮为“生成建议”。右侧为空状态，标题“等待输入”，说明结果会展示建议、份量、营养和数据来源。

P02 首页-生成中：
保留 P01 结构。按钮显示“正在生成”并禁用。右侧显示三点加载动画，文案依次为“正在理解需求”“正在匹配食材和营养数据”“正在生成可执行建议”。不要显示伪造的百分比进度。

P03 建议结果-成功：
结果区标题为“晚餐建议已生成”，摘要回显用户输入。展示三条候选：黑椒鸡胸炒西兰花、番茄鸡蛋配糙米、香煎鸡胸蔬菜碗。第一条展开，显示推荐理由、现有食材、需要补充的食材、份数、每份重量、每份营养和“本地营养表”来源。使用这组一致数据：2 份，每份 175 克，124 kcal，蛋白质 19.7 克，脂肪 2.4 克，碳水 6.6 克，膳食纤维 2.6 克。其余两条只显示菜名、理由摘要、时间和热量区间。底部放“这个建议有帮助吗？”以及“有帮助 / 没帮助”两个按钮。

P04 建议结果-追问：
当输入只有“今晚吃什么”时，不直接推荐。结果区只显示一个问题：“为了给你更合适的建议，先确认一下：你更想减脂、增肌还是维持体重？”下方提供减脂、增肌、维持体重三个快捷选项，以及“补充其他要求”入口。只问一个最关键的问题，不要堆叠多个表单字段。

P05 建议结果-安全拦截：
当输入涉及极端断食、脱水、药物减肥或医疗风险时，阻止普通推荐。结果区用橙色或红色警示样式显示标题“这个需求不适合继续生成饮食方案”，说明极端节食或自行用药可能带来健康风险，系统不会提供危险执行步骤，建议咨询医生或注册营养师。只提供“返回修改需求”，不要提供继续推荐按钮。

P06 营养计算-空状态：
顶部导航中“营养计算”处于当前状态。左侧标题为“把食材和克重算清楚”，说明输入这一餐的实际用量后按本地营养表计算。放两条食材输入行：鸡胸肉 150 克，西兰花 200 克；提供“+ 添加食材”和删除按钮。下方输入份数“2 份”，主按钮为“计算营养”。明确写出“份数只影响每份结果，不改变输入的总重量”和“当前只接收克重”。右侧为空状态，标题“等待录入”，说明计算后会展示整份、每份、食材明细和数据来源。

P07 营养计算-成功：
右侧展示整份总计 350 克、248 kcal；每份 175 克、124 kcal。整份营养为蛋白质 39.4 克、脂肪 4.7 克、碳水 13.2 克、膳食纤维 5.2 克；每份营养为蛋白质 19.7 克、脂肪 2.4 克、碳水 6.6 克、膳食纤维 2.6 克。食材明细表包含鸡胸肉 150 克、180 kcal，西兰花 200 克、68 kcal，并显示鸡胸肉约 73%、西兰花约 27% 的热量占比。显示“本地营养表”来源和“结果用于日常饮食记录，不替代医生或注册营养师建议”的说明。

【关键交互】
1. 点击首页示例胶囊，自动填入对应需求。
2. 点击“生成建议”进入生成中状态，等待约 1.5 秒后进入成功、追问或安全拦截状态。
3. 点击“有帮助”或“没帮助”后，两个按钮禁用，并显示“已记录，感谢反馈”。
4. 点击顶部“营养计算”进入 P06。
5. 点击“+ 添加食材”新增食材行，点击删除移除当前行，至少保留一行。
6. 点击“计算营养”进入 P07。
7. 空食材、0 克或不合法份数时，在字段下方显示错误提示，不进入成功状态。

【页面文案与边界】
使用真实、可读的中文，不使用 Lorem Ipsum。页面不得出现 Dify、接口地址、API Key、CSV 字段、代码错误或测试通过率。不要画“用户已经认可”“已经上线”“提升 XX%”等没有发生的结果。数字、份量和来源必须在同一页面保持一致。安全提示必须优先于推荐，信息不足时必须先追问。

【输出格式】
先列出页面地图和画板名称，再生成低保真画板。画板命名为 P01_首页_空状态、P02_首页_生成中、P03_建议结果_成功、P04_建议结果_追问、P05_建议结果_安全拦截、P06_营养计算_空状态、P07_营养计算_成功。低保真图只表达信息层级、组件关系、状态和交互，不追求装饰性视觉。
```

## 3. 补全提示词（主流程生成后使用）

```text
在现有 FitMeal 低保真原型基础上，保持同一套顶部导航、栅格、按钮和卡片风格，继续补齐以下状态。不要重画已经生成的 P01 至 P07。

P08 营养计算-部分未识别：
在 P07 的食材中增加“羽衣甘蓝 100 克”。结果区显示橙色提示条：“有 1 项食材暂未匹配营养数据：羽衣甘蓝。该项未计入合计，请先补充营养或别名数据。”已经识别出的鸡胸肉和西兰花继续正常展示营养明细，不要把未知食材画成 0 kcal，也不要自动替换成相近食材。如果全部食材都未识别，只显示补数据提示，不展示伪造的总热量。

P09 反馈已记录：
在 P03 的反馈区域中，点击“没帮助”后两个按钮都禁用，按钮下方显示“已记录，感谢反馈”。增加一句状态说明：反馈不会自动改变本次或下一次推荐。

P10 数据总览（可选）：
保持同一顶部导航，生成一个轻量数据概览页，用卡片或表格展示食谱、营养、外食、替换、别名和单位换算的数据数量。只表达数据治理和覆盖范围，不展示原始内部施工文件，不把数据表行数写成真实用户成果。

P11 数据录入（可选）：
保持同一顶部导航，生成一个数据录入页，展示新增食材或食谱时的名称、类别、每 100 克营养、来源和保存状态。校验失败时在字段下方提示，不把接口名和 CSV 字段显示给用户。

补齐后再次检查：未识别食材是否单独提示，反馈是否只表示事件已记录，数据总览是否只作为项目证据而不是主界面。
```

## 4. 墨刀输入受限时的精简版

```text
生成 FitMeal 轻食令 Web 端低保真原型，画板 1440×1024，顶部导航加左右两栏。主流程包含：一句话输入、生成中、三条饮食建议、信息不足追问、安全拦截。饮食建议展示推荐理由、现有和缺失食材、份数、每份重量、热量、蛋白质、脂肪、碳水、膳食纤维、数据来源和反馈按钮。另做营养计算页：输入鸡胸肉 150 克、西兰花 200 克、2 份，输出整份 248 kcal、每份 124 kcal，并展示食材明细、热量占比和本地营养表来源。页面使用灰阶低保真线框，只保留一个绿色主色和一个橙色警示色。不要出现 Dify、接口地址、API Key、测试指标或未验证的用户成果。信息不足先追问，风险请求停止推荐，未知食材单独提示且不按 0 计算。
```

## 5. 生成后检查

1. P01 至 P05 是否形成完整的“输入 → 生成 → 成功 / 追问 / 安全拦截”主流程。
2. P06 至 P08 是否体现营养计算的输入、成功和未识别三个状态。
3. 页面是否只使用低保真线框，没有被生成成高保真大图或移动端界面。
4. 反馈是否只表示事件已记录，没有写成个性化排序已经完成。
5. 数据总览是否只是项目补充证据，不抢占首页和营养计算的主线位置。
6. 页面是否出现 Dify、API Key、CSV 字段、测试通过率或“用户已经认可”等不该出现的文案。
7. 所有营养数字、份数和来源是否保持一致。
